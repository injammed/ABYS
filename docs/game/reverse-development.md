# AETIMM: build backward from the ending

The primary desktop playtest entry is the APY0C endgame lab. Finish and validate the ending before expanding its prerequisites. APY0C is the fictional Horizon Mind and the proposed authoring director; the user decides canon. No autonomous model-powered agent is running or spending funds in this prototype.

1. APY0C encounter: duelist, eight-legged void dragon with crater attacks and falling pillars, then dragon-fused armor. Current low-poly encounter is a playable prototype, not source-image visual parity.
2. Horizon Mind interior and aftermath: motivation, choices, victory and failure, player arrival conditions.
3. Outer Horizon habitat: the approach, vehicles, traversal and boss unlock conditions.
4. Galactic journey and ship systems: establish how the player reaches the habitat.
5. Earth campaign: infection, possession, machines, rescue and augmentation must lead to the established ending.
6. Cathedral opening: teach mechanics and establish the stakes from the beginning.

The authoring loop is user input in the production chat → inspect current source and this contract → code a scoped change → automated verification → merge → publish a versioned game-content pack. The native app checks that channel, stages a checksum-verified build and activates it between sessions. A previous build and local saves remain separate. Chat cannot silently control a laptop, read local files, or observe playtests: the user describes a bug and may attach the exported diagnostic/save file.

A future APY0C authoring agent should propose scoped changes with provenance, run tests in an isolated workspace, and submit reviewable source changes. It must not override user canon, deploy unchecked code, acquire credentials, or spend resources without an explicit project authorization. These are future capabilities, not claims about the shipped updater.
