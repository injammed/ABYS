# Built by Slop: Public Build Provenance

## Status

ABYS runtime doctrine for `aetimm.com`.

The site should be openly machine-assisted, visibly iterative, and publicly inspectable.

```txt
Vibe-coded.
AI-assisted.
Human-directed.
Steel-folded in production.
```

The phrase **Built by Slop** is not an excuse for unreliable software. It names the raw generative material. The steel-fold process is what converts that material into functioning infrastructure.

## Core Product Law

`aetimm.com` should possess meta-awareness of its own construction.

The site is simultaneously:

1. a destination for AI-made artifacts;
2. a filter that separates signal from synthetic excess;
3. an artifact built through human–machine collaboration;
4. a public demonstration of how generated code becomes reliable through repeated testing and correction;
5. the visible gravity well into which synthetic media is submitted, judged, routed, preserved, refined, or contained.

## Honest Public Claim

Use this public formulation:

```txt
Built by slop. Directed by a human. Folded into working software through public commits, tests, deployments, and field verification.
```

Do not claim the site was built autonomously unless a particular change actually was.

Do not imply that every commit was generated by AI.

Every public attribution should distinguish:

- human direction;
- machine-generated proposal or code;
- manual implementation;
- automated validation;
- production field verification.

Each entry should answer:


Suggested shape:

```ts

    device: string;
    browser: string;
```

## Build DNA

The site should expose a small machine-readable manifest:

```txt
/build-manifest.json
```

Recommended fields:

```json
{
  "product": "aetimm.com",
  "repository": "injammed/ABYS",
  "runtimePath": "apps/item-web",
  "buildMode": "human-directed-ai-assisted",
  "productionCommit": "<sha>",
  "deployedAt": "<timestamp>",
  "steelFold": 3,
  "openCompletionIssue": 39
}
```

Generate values during deployment where practical. Never hard-code a false current SHA or deployment timestamp.

The public repository is not merely a developer utility. It is part of the work.

The repository demonstrates:

- the prompt-to-plan layer;
- generated and manually edited code;
- bounded repair issues;
- failed assumptions;
- pull-request diffs;
- CI results;
- production field evidence;
- the difference between raw generation and durable implementation.

The commits become provenance for the website as a Full-Mode Artifact.

## Prompt and Conversation Disclosure

Public build provenance should not automatically dump complete private conversations or hidden reasoning.

Publish only selected, intentional material:

- task packets;
- public issues;
- sanitized prompts;
- implementation summaries;
- commit history;
- test and deployment records.

Never expose:

- private credentials;
- authentication tokens;
- private user data;
- service-role keys;
- private email contents;
- unreviewed personal conversation history.
