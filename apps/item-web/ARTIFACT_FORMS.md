# AETIMM Artifact Forms Covenant

## Semantic Form Is Not Modality

AETIMM accepts works, systems, demonstrations, lessons, plans, packages, and tools as Artifacts.

A creator may describe an Artifact as a:

- course or class;
- personal bot or agent;
- business model or operating playbook;
- research package;
- startup concept;
- design system;
- scientific experiment;
- interactive demonstration;
- game, application, simulation, or other machine-made experience.

These are **semantic forms**, not new media modes and not new products.

The system must not create `course`, `bot`, `business_model`, `research`, or similar top-level modality enums merely because creators use those words to describe what their Artifact does.

Instead, semantic forms are composed from the universal material vocabulary already carried by the Artifact manifest:

```txt
image
video
audio
text
document
code
data
model3d
website
simulation
other
```

The Artifact is judged as a whole.

---

## Example: AI-Generated Course

A complete AI-generated class can be one Artifact:

```txt
PERSONAL TRADING BOT CLASS

00 · video     · introduction.mp4
01 · document  · course-notes.pdf
02 · code      · example-bot.py
03 · data      · sample-backtest.csv
04 · text      · lesson-plan
05 · website   · external-reference
```

That is one Artifact, one identity, one quarantine object, one feed landing, and one Slop / Museum judgment.

It does not require a `course` feed or a special course uploader.

---

## Example: Business Model

An AI-generated business model may contain:

```txt
00 · document  · business-plan.pdf
01 · data      · unit-economics.csv
02 · image     · product-concept.png
03 · video     · product-walkthrough.mp4
04 · code      · prototype.zip
05 · text      · operating-playbook
```

Again: one Artifact.

A business plan is not privileged over an image and does not bypass Unjudged.

## Capability Boundary

Acceptance does not imply execution authority.

A bot, agent, trading system, application, or automation may be stored, inspected, demonstrated, and judged as an Artifact while its executable-capable components remain inert during intake.

For example, a trading-bot Artifact may contain source code, strategy documentation, example data, backtest evidence, and a walkthrough. Universal intake does **not** automatically:

```txt
connect to a broker
connect to an exchange
request financial credentials
place trades
run uploaded source code
fetch arbitrary external resources
```

If a future trusted runtime permits execution, that runtime receives its own sandbox, capability grants, resource limits, network policy, and explicit threat model. The Artifact identity and feed lifecycle remain unchanged.

---

## One Feed Law

Semantic form never creates a new public discovery destination.

There is no separate:

```txt
course feed
bot feed
business-model feed
agent feed
game feed
simulation feed
```

Public discovery remains the same infinite Artifact feed.

```txt
SUBMIT

[ ARTIFACT ]

← SLOP      MUSEUM →

scroll
```

A new kind of machine creation should normally require a new safe renderer or processor—not a new product surface.

---

## Engineering Test

When a future contributor encounters a new creation such as an AI tutor, autonomous research package, generated corporation plan, personal software agent, or media form not yet invented, ask:

> Can this be represented as one Artifact manifest and experienced through a trusted runtime?

If yes, fold it into the existing system.

Do not create another feed.
